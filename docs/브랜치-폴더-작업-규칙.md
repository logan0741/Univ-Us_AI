# 브랜치별 폴더 작업 규칙

우리 팀은 **브랜치 1개 = 폴더 1개** 원칙으로 작업한다.
`C:\Project\Univ-Us_AI\` 는 컨테이너 폴더라서 **안에는 브랜치 폴더만 둔다**
(소스 파일을 직접 두지 않는다). 폴더 이름은 `Univ_Us_<브랜치명>`,
브랜치 이름은 `<기능>_<github아이디>` 형식으로 짓는다.

```text
C:\Project\Univ-Us_AI\                      ← 컨테이너 (브랜치 폴더만 있음)
├── Univ_Us_main\                           ← main 브랜치 (pull 전용, 직접 수정 금지)
├── Univ_Us_collect_ai-agent_logan0741\    ← 수집 기능 작업
└── Univ_Us_train_hong1234\                ← 학습 기능 작업 (예시)
```

> 각 폴더는 독립된 clone 이다. 작업할 폴더를 VS Code 로 열고
> 그 안에서 자유롭게 커밋·푸시하면 된다.

## VS Code 에서 브랜치별로 보기·푸시하기

컨테이너에 있는 **`Univ-Us_AI.code-workspace`** 파일을 VS Code 로 열면
(더블클릭 또는 `File → Open Workspace from File`)
브랜치 폴더들이 한 창에 나란히 뜨고, **Source Control 패널에 repo 가 브랜치별로
따로 표시**된다. 커밋·푸시도 repo 별로 각각 하면 된다.

- 새 브랜치 폴더를 만들었으면 `.code-workspace` 파일의 `folders` 목록에 한 줄 추가한다
  (또는 폴더를 창에 드래그 → `Workspace 에 폴더 추가`).
- `C:\Project\Univ-Us_AI` 폴더를 그냥 열어도 VS Code 가 하위 repo 를 자동 감지한다.
  워크스페이스 파일은 이름표가 붙어 더 보기 좋을 뿐이다.

> 저장소: https://github.com/logan0741/Univ-Us_AI (public — clone 에 인증 불필요, push 는 GitHub 로그인 필요)

## 1. 처음 세팅 (1회)

main 폴더를 만든다. 이 폴더는 **최신 main 을 받아보는 용도**로만 쓴다.

```powershell
git clone -b main https://github.com/logan0741/Univ-Us_AI.git C:\Project\Univ-Us_AI\Univ_Us_main
```

## 2. 새 기능 시작할 때

main 을 기준으로 새 폴더 + 새 브랜치를 만든다.

```powershell
# <기능>_<아이디> 를 자기 것으로 바꿔서 실행 (예: parser_hong1234)
$branch = "<기능>_<아이디>"
git clone -b main https://github.com/logan0741/Univ-Us_AI.git C:\Project\Univ-Us_AI\Univ_Us_$branch
cd C:\Project\Univ-Us_AI\Univ_Us_$branch
git switch -c $branch
git push -u origin $branch
```

이후 이 폴더 안에서만 해당 기능을 작업한다.

## 3. 작업 중 (커밋 · 푸시)

```powershell
git add .
git commit -m "[feat] 무엇을 했는지"
git push
```

- 커밋 메시지는 `[feat]` `[fix]` `[docs]` `[chore]` 접두어를 붙인다.
- 하루 작업 끝나면 반드시 push (다른 사람이 볼 수 있게).

## 4. 기능 완료 → main 에 합치기

1. GitHub 에서 **Pull Request** 생성: `내 브랜치 → main`
2. 팀원 확인 후 **Merge**
3. 각자 main 폴더 최신화:
   ```powershell
   cd C:\Project\Univ-Us_AI\Univ_Us_main
   git pull
   ```

## 5. 다른 사람 브랜치 받아보기

```powershell
git clone -b <브랜치명> https://github.com/logan0741/Univ-Us_AI.git C:\Project\Univ-Us_AI\Univ_Us_<브랜치명>
```

이미 받아둔 폴더면 그 폴더에서 `git pull` 만 하면 된다.

## 6. 내 브랜치에 main 최신 내용 반영하기

main 이 앞서갔을 때 (다른 기능이 먼저 머지됐을 때):

```powershell
cd C:\Project\Univ-Us_AI\Univ_Us_<내브랜치>
git fetch origin
git merge origin/main
# 충돌나면 해결 후 git add . ; git commit
git push
```

## 주의사항

- **Univ_Us_main 폴더에서는 절대 직접 수정·커밋하지 않는다.** main 은 PR 머지로만 바뀐다.
- 기능이 머지된 브랜치 폴더는 지워도 된다 (기록은 GitHub 에 남는다).
- `.pem` 키, `data/` 대용량 파일은 커밋 금지 (`.gitignore` 에 이미 등록됨).
- push 가 처음이면 브라우저로 GitHub 로그인 창이 뜬다 (Git Credential Manager). 본인 계정으로 로그인하면 된다.
- 커밋 전에 `git config user.name` / `git config user.email` 이 본인 것인지 확인:
  ```powershell
  git config user.name  "본인 github 아이디"
  git config user.email "본인 이메일"
  ```
  (폴더 안에서 실행하면 그 폴더에만 적용됨)
