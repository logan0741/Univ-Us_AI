# 서버 작업환경 설정

> **서버에 접속한 다음** 개발을 시작하기까지의 설정을 다룹니다.
> 접속 자체가 안 된다면 먼저 [SSH 서버 접속 가이드](SSH-서버-접속-가이드.md)를 보세요.

| 이 문서가 답하는 것 |
| --- |
| pod 를 재시작했더니 설치한 게 다 사라졌어요 |
| 터미널을 열었는데 venv 가 안 켜져요 |
| `git push` 가 안 돼요 (`could not read Username`) |
| `gh` 를 설치했는데 재시작하니 없어졌어요 |

---

## 1. 먼저 알아야 할 것 — 무엇이 남고 무엇이 사라지나

학교 서버는 Kubernetes pod 입니다. **경로에 따라 영속성이 다릅니다.**

| 경로 | 저장소 | pod 재시작 시 |
| --- | --- | --- |
| `/home/jovyan` (홈) | CephFS 영구 볼륨 (10GB) | **남음** ✅ |
| `~/.ssh` · `~/.local/bin` · `~/.bashrc` | 위와 같음 | **남음** ✅ |
| 클론한 저장소 | 위와 같음 | **남음** ✅ |
| **`~/.venv/*`** | `/home/jovyan_venv` 심볼릭 링크 → 컨테이너 overlay | **사라짐** ❌ |
| `/usr` · `/opt` (`apt install` 대상) | 컨테이너 overlay | **사라짐** ❌ |

```bash
ls -l ~/.venv          # 심볼릭 링크인 것을 직접 확인할 수 있습니다
df -h ~ ~/.venv        # 마운트가 다릅니다
```

여기서 두 가지 원칙이 나옵니다.

1. **도구는 `~/.local/bin` 에 설치한다.** `sudo apt install` 은 재시작하면 사라집니다.
2. **venv 는 사라지는 걸 전제로 한다.** 대신 [재설치를 명령 한 줄로](#2-개발-환경-설치--재설치) 만들어 둡니다.

> 홈 볼륨은 10GB 뿐입니다(`df -h ~`). venv 하나가 8GB 라 홈에는 애초에 들어가지 않습니다.
> venv 가 overlay 에 있는 건 사고가 아니라 용량 때문입니다.

## 2. 개발 환경 설치 / 재설치

```bash
cd ~/Univ-Us_AI
bash scripts/setup-gpu-env.sh
```

이 한 줄이 아래를 전부 합니다.

- `~/.venv/univus-ai` venv 생성
- `requirements.txt` + `requirements-dev.txt` 설치
- **GPU 가 있으면** `requirements-gpu.txt` 까지 설치 (`nvidia-smi` 로 자동 판단)
- Jupyter 커널 `Univ-Us AI` 등록 (커널은 홈에 저장되어 재시작해도 남습니다)
- torch·CUDA 동작 검증 + `nvitop` 출력

이미 설치돼 있으면 건너뛰므로 **여러 번 실행해도 안전합니다.**

### 오래 걸리니 세션과 분리해서 돌리세요

GPU 포함 시 6GB 정도 받습니다. 터미널을 닫아도 계속 돌게 하려면:

```bash
setsid nohup bash scripts/setup-gpu-env.sh > ~/setup.log 2>&1 < /dev/null &
tail -f ~/setup.log          # Ctrl+C 로 로그만 빠져나옴 (설치는 계속)
grep STATUS= ~/setup.log     # DONE 이면 성공, FAILED 면 실패
```

### 옵션

```bash
SKIP_GPU=1 bash scripts/setup-gpu-env.sh          # GPU 패키지 빼고
VENV=~/.venv/실험용 bash scripts/setup-gpu-env.sh   # 다른 경로에
```

## 3. 터미널에서 venv 자동으로 켜기

`~/.bashrc` 끝에 아래를 넣습니다.

```bash
# venv 자동 활성화
#  · 절대경로를 쓴다 — 상대경로면 홈이 아닌 곳에서 연 터미널에서 실패한다
#  · 있을 때만 source 한다 — .venv 는 재시작 시 사라진다
if [ -f "$HOME/.venv/univus-ai/bin/activate" ]; then
    source "$HOME/.venv/univus-ai/bin/activate"
fi
```

> ### 상대경로로 쓰면 안 되는 이유
> `source .venv/.../activate` 처럼 `$HOME` 없이 쓰면, **홈 디렉터리에서 연 터미널에서만** 동작합니다.
> VS Code 터미널은 워크스페이스 폴더(`~/Univ-Us_AI`)에서 열리므로 **매번 조용히 실패**합니다.
> 그 상태로 `pip install` 을 하면 venv 가 아니라 시스템 파이썬에 깔립니다.

확인:

```bash
echo $VIRTUAL_ENV        # /home/jovyan/.venv/univus-ai
which python             # 위 경로 아래의 python
```

## 4. GitHub 에 push 하기 — SSH 키 등록

HTTPS 로 클론했다면 push 할 때 이 오류가 납니다.

```
fatal: could not read Username for 'https://github.com'
```

GitHub 은 2021년부터 비밀번호 인증을 막았습니다. **SSH 키**를 쓰는 것이 가장 간단합니다.
(`~/.ssh` 는 영구 볼륨이라 한 번 만들면 재시작해도 남습니다.)

### 4-1. 키 만들기

```bash
ssh-keygen -t ed25519 -C "본인GitHub이메일" -f ~/.ssh/id_ed25519 -N ""
chmod 600 ~/.ssh/id_ed25519
```

### 4-2. 공개키를 GitHub 에 등록

```bash
cat ~/.ssh/id_ed25519.pub      # 이 한 줄을 통째로 복사
```

<https://github.com/settings/ssh/new> 에서 **Key type: Authentication Key** 로 붙여넣고 저장합니다.

> **`.pub` 가 공개키입니다.** 이건 노출돼도 안전합니다.
> 확장자 없는 `id_ed25519` 가 개인키이며, **절대 공유하지 마세요.**

### 4-3. remote 를 SSH 로 바꾸고 확인

```bash
git remote set-url origin git@github.com:logan0741/Univ-Us_AI.git
ssh -T git@github.com          # "Hi <사용자명>!" 나오면 성공
git push origin main
```

> ### 서버 접속용 키와 헷갈리지 마세요
> [SSH 서버 접속 가이드](SSH-서버-접속-가이드.md)의 키는 **내 PC → 학교 서버** 접속용입니다.
> 여기서 만드는 키는 **학교 서버 → GitHub** 용으로, 서로 다른 키입니다.

## 5. GitHub CLI (`gh`) 설치

칸반 보드 세팅([scripts/setup-kanban.sh](../scripts/setup-kanban.sh))에 필요합니다.

### 5-1. 설치 — `apt` 말고 `~/.local/bin` 에

```bash
VER=2.97.0        # 최신 버전은 https://github.com/cli/cli/releases 확인
mkdir -p ~/.local/bin
cd /tmp
curl -sSL -o gh.tar.gz "https://github.com/cli/cli/releases/download/v${VER}/gh_${VER}_linux_amd64.tar.gz"
tar -xzf gh.tar.gz
cp "gh_${VER}_linux_amd64/bin/gh" ~/.local/bin/gh
chmod +x ~/.local/bin/gh
```

`~/.bashrc` 에 경로 등록 (한 번만):

```bash
export PATH="$HOME/.local/bin:$PATH"
```

> `sudo apt install gh` 는 `/usr` 에 깔려서 **재시작하면 사라집니다.** 홈 아래에 설치하세요.

### 5-2. 로그인

```bash
gh auth login
```

| 질문 | 선택 |
| --- | --- |
| What account do you want to log into? | GitHub.com |
| Preferred protocol for Git operations? | SSH |
| Upload your SSH public key? | 이미 등록했다면 **Skip** |
| How would you like to authenticate? | **Login with a web browser** |

서버에는 브라우저가 없으므로 **일회용 코드**가 출력됩니다. 정상입니다.
코드를 복사해 **본인 PC 브라우저**에서 <https://github.com/login/device> 에 입력하세요.

### 5-3. `project` 권한 추가 ⚠️ 빠뜨리기 쉬움

기본 로그인은 `repo` 권한만 줍니다. **칸반 보드에 카드를 넣으려면 `project` 권한이 따로 필요합니다.**

```bash
gh auth refresh -s project
gh auth status                 # Token scopes 에 'project' 가 보여야 합니다
```

이걸 안 하면 **이슈는 만들어지는데 보드에 카드만 안 들어갑니다.** 원인을 찾기 어려운 실패라 미리 해두세요.

## 6. HTTPS 인증서 오류

`pip` 은 되는데 코드에서만 HTTPS 가 실패한다면 CA 인증서 경로 문제입니다.

```bash
export SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt
```

원인과 상세는 [README 9장](../README.md)에 정리돼 있습니다.
**`verify=False` 로 우회하지 마세요.**

## 7. pod 재시작 후 복구 체크리스트

재시작되면 **venv 만** 날아갑니다. 나머지는 그대로 있습니다.

```bash
# 1. 남아 있는지 확인 (전부 있어야 정상)
ls ~/.ssh/id_ed25519 && which gh && ls ~/Univ-Us_AI

# 2. venv 재설치 — 이것만 하면 됩니다
cd ~/Univ-Us_AI && bash scripts/setup-gpu-env.sh

# 3. 확인
source ~/.venv/univus-ai/bin/activate
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

| 항목 | 재시작 후 |
| --- | --- |
| SSH 키 · `gh` · `.bashrc` · 저장소 · Jupyter 커널 등록 | 그대로 남음 — 할 일 없음 |
| venv (`~/.venv/univus-ai`) | **재설치 필요** — 위 2번 |

## 8. GPU 를 쓸 때 알아둘 것

학교 서버의 A100 은 **MIG 로 쪼개서** 나눠 씁니다. 카드 전체가 내 것이 아닙니다.

```bash
nvitop -1        # 나에게 할당된 슬라이스 확인
```

```
0:0   1g.10gb @ GI/CI:11/0   35.50MiB / 9728MiB
```

이렇게 나오면 **쓸 수 있는 VRAM 은 약 9.5GiB** 입니다. 80GB 가 아닙니다.
`torch.cuda.get_device_name(0)` 도 `NVIDIA A100 80GB PCIe MIG 1g.10gb` 로 나옵니다.

**배치 크기와 모델 크기를 9.5GiB 기준으로 잡으세요.** 큰 모델 풀 파인튜닝은 불가능하고,
LoRA 같은 경량 학습이나 작은 모델을 써야 합니다. 관련 판단은 [DEV_PLAN](DEV_PLAN.md) 3장을 참고하세요.
