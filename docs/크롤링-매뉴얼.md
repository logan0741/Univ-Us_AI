# 데이터 수집(크롤링) 상세 매뉴얼

> `src/collect/` 모듈의 **전체 동작·데이터 저장 방식**을 세세하게 설명합니다.
> 빠른 사용법만 필요하면 [크롤링-사용법.md](크롤링-사용법.md) 를, 설계 배경은
> [수집_파이프라인_계획서](../수집_파이프라인_계획서.md) 를 보세요.

---

## 0. 한눈에

```
[로그인]                [수집]                     [저장]                [파싱]
weblogin(noVNC) ─세션─▶ collect timetable/syllabus ─원문─▶ data/raw ─▶ parse ─▶ data/processed
                        collect(공개게시판) notices        data/meta          (구조화 JSON)
                                                           data/index (중복판별)
                                                           data/runlog (실행이력)
```

- **로그인이 필요한 것**(내 시간표·계획서): `weblogin` 으로 세션을 만든 뒤 `collect`.
- **로그인이 필요 없는 것**(학과·사업단 공지): 바로 `notices`.
- 수집은 **원문을 그대로 보존**(§5.1)하고, 구조화는 별도 단계(`parse`)로 나눕니다.
- 모든 산출물은 `data/` 아래에 저장되며 **git 에 올라가지 않습니다**(`.gitignore`).

## 1. 수집 대상과 방식

| 소스 | 명령 | 로그인 | 방식 | 결과물 |
| --- | --- | :---: | --- | --- |
| 개인 시간표 | `collect timetable` | 필요 | 세션+브라우저 | 원문 HTML → 구조화 JSON |
| 강의계획서 | `collect syllabus` | 필요 | 세션+브라우저+PDF | 과목별 계획서 PDF |
| 수강내역 | `collect sugang_courses` | 필요 | 세션+브라우저 | 원문 HTML(수강신청 기간 한정) |
| eClass 과제 | `collect eclass` | 필요 | 세션+ICS/HTML | .ics 또는 대시보드 HTML |
| 학과 공지(aisw) | `notices aisw` | 불필요 | httpx+전페이지 | 목록 JSON + 상세 본문 JSON |
| 사업단 공지(aicoss/nccoss/sojoong) | `notices <site>` | 불필요 | httpx+전페이지 | 〃 |

## 2. 로그인 (weblogin) — 세션은 어떻게 만들어지나

학사 페이지는 **통합인증(SAML) + 2차 인증(휴대폰 앱/OTP)** 뒤에 있습니다.
헤드리스 서버에는 화면이 없어서, **실제 브라우저를 서버에 띄우고 그 화면을 웹으로 넘겨**(noVNC)
사용자가 직접 로그인합니다. 코드: [`src/collect/weblogin.py`](../src/collect/weblogin.py)

```
python -m src.collect.cli weblogin
  1) 서버에 Xvfb(가상화면) + 실제 크롬 + x11vnc + noVNC 를 띄움
  2) 크롬이 hakstd 로그인 페이지로 이동 (sso.jnu.ac.kr 통합인증)
  3) 사용자가 SSH 포트포워딩(localhost:6080)으로 접속해 직접 로그인(비번+폰 인증)
  4) 터미널에서 Enter → 그 시점 브라우저의 쿠키 전체를 저장
```

- **비밀번호는 저장·기록하지 않습니다.** 사용자가 실제 로그인 페이지에 직접 입력하고,
  프로그램은 그 결과 **세션 쿠키만** 저장합니다.
- 설치는 최초 1회(+재시작 후) `bash scripts/setup-weblogin.sh`.
- 자세한 절차·문제 해결은 [크롤링-사용법.md](크롤링-사용법.md).

### 세션 파일 — `data/sessions/jnu_storage_state.json`

Playwright `storage_state` 형식입니다. **쿠키만** 들어있고 비밀번호는 없습니다.

```json
{
  "cookies": [
    {"name":"...", "value":"...", "domain":".jnu.ac.kr", "path":"/",
     "expires":..., "httpOnly":true, "secure":true, "sameSite":"Lax"}
  ],
  "origins": []
}
```

- 이 파일은 **살아있는 인증**이라 비밀번호만큼 민감합니다. `.gitignore` 로 이중 차단.
- 세션이 만료되면 `collect` 가 `login_required` 로 멈춥니다 → `weblogin` 재실행.
- **서버에서 로그인한 세션은 서버 IP 로 생성**되므로, 서버에서 `collect` 할 때
  IP 바인딩 문제가 없습니다.

## 3. 로그인 필요 수집 (collect) — 내부 동작

공통 흐름은 [`base.py`](../src/collect/base.py) 의 `Collector.run()` 이 담당합니다.

```
세션으로 브라우저 열기 → fetch_items(page) → 각 항목을 원문 저장 → 실행로그
  · 로그인 페이지로 튕기면 LoginRequired → "login_required" 기록 후 정지 (§4.4)
  · 예외는 조용히 삼키지 않고 "failed" 로 기록
  · 항목 사이에 요청 간격(JNU_COLLECT_MIN_INTERVAL_SEC, 기본 3초) (§6)
```

### 3-1. 시간표 (`timetable`)

- `hakstd.jnu.ac.kr/web/Suup/Suup090` 페이지를 세션으로 열어 **렌더된 HTML 전체**를 저장.
- 원문에는 7열 그리드(시간·월~토)와 과목 셀이 들어있어 파서로 구조화합니다(§5).

### 3-2. 강의계획서 (`syllabus`) — 과목별 PDF 드릴다운

가장 복잡합니다. 코드: [`sources/syllabus.py`](../src/collect/sources/syllabus.py)

```
1. 시간표를 열어 내 수강과목(과목코드·분반) 파싱
   예: DSC0010-1 인공지능로봇실습, ...
2. 계획서조회(Suup051)에서 과목명으로 검색
3. 결과행의 OpenDown(과목,분반,년도,학기,교수번호,종류,언어) 링크를
   한국어(LANG=KOR)로 재호출 → ClipReport 리포트 뷰어(rptbi) 팝업
4. 뷰어의 "PDF 저장" 버튼 클릭 → 계획서 PDF 다운로드 → 원문 저장
```

- 대상 학기는 `.env` 의 `SYLLABUS_YY`(2026)·`SYLLABUS_TERM`(2).
- 결과: 과목당 PDF 1개. 계획서 본문(주별계획·평가·과제·시험)이 그대로 들어있어
  이후 `doc_ai-agent` 가 과제·시험 일정을 추출합니다.

### 3-3. eClass (`eclass`)

- `sel.jnu.ac.kr` 은 Moodle 입니다. `.env` 의 `JNU_ECLASS_ICS_URL` 이 있으면
  캘린더 `.ics` 를 받아 저장(권장), 없으면 대시보드 HTML 을 저장(폴백).

### 3-4. 수강내역 (`sugang_courses`)

- `sugang.jnu.ac.kr/Pages/Suup080`. **수강신청 기간에만 열립니다.**
  기간 종료 후에는 로그인 페이지로 튕겨 `login_required` 가 됩니다(정상).

## 4. 공개 게시판 공지 수집 (notices) — 내부 동작

로그인이 필요 없어 브라우저 없이 **httpx** 로 받습니다. 코드: [`notice.py`](../src/collect/notice.py)

### 4-1. 대상과 파서

게시판마다 구조가 달라 파서를 개별 구현합니다(§3.3).

| 사이트 키 | 게시판 | CMS | 파서 |
| --- | --- | --- | --- |
| `aisw` | 인공지능학부(학과) | 전남대 CMS(artclView) | `jnu_cms` |
| `aicoss` | 인공지능혁신융합사업단 | movePageView 게시판 | `kboard` |
| `nccoss` | 차세대통신혁신융합사업단 | 〃 | `kboard` |
| `sojoong` | 소프트웨어중심사업단 | 워드프레스 KBoard | `wp_kboard` |

### 4-2. 수집 절차

```
1. robots.txt 확인 — 금지면 즉시 중단 (urllib.robotparser)
2. 1페이지부터 순회하며 목록 파싱 (제목·URL·날짜·구분)
   · 사이트별 페이지 파라미터: sojoong=pageid, 나머지=page
   · URL 정규화로 페이지 파라미터 제거(중복판별용)
   · 새 글이 없는 페이지를 만나면 자동 정지 (기본 최대 100페이지)
3. 목록 전체를 processed JSON 으로 저장
4. 아직 안 받은(신규) 공지의 상세 페이지를 요청 간격 두고 받아옴
   · 상세 HTML 에서 네비/헤더/푸터 제거 후 본문·첨부파일 추출
   · 원문 HTML 은 raw 로 보존, 구조화(제목·날짜·본문·첨부)는 processed 로 저장
```

### 4-3. 상세 URL 이 사이트마다 다른 점

- `aisw`: 목록 링크가 직접 URL(`/bbs/.../artclView.do`).
- `aicoss`·`nccoss`: 목록은 `movePageView(id)` JS → 실제 상세는 `view/{id}?bd=notice`.
  (초기 구현이 `?mod=document&uid=` 로 잘못 가서 목록을 받던 버그를 교정했습니다.)
- `sojoong`: 직접 URL(`?uid=..&mod=document`)이나 **페이지마다 `pageid` 가 붙어**
  같은 공지가 다른 URL 로 보임 → 정규화로 중복 제거.

### 4-4. 카테고리 분류는 하지 않습니다

지금은 사이트가 주는 **구분값**(`일반공지`, `Notice`, 게시물번호 등)만 그대로 담습니다.
실제 분류(장학/모집/행사…)와 자격요건 추출은 **나중에 `notice_ai-agent` 가 LLM 으로** 합니다.

## 5. 데이터 저장 방식 — 어디에, 어떤 형식으로

모든 산출물은 `data/` 아래에 저장되고 **git 에 올라가지 않습니다**(`.gitignore` 의 `data/*`).
원문 보존 원칙(§5.1): **변환 전 원문을 반드시 남긴다.** 파싱 로직을 개선하면 원문을 재처리합니다.

### 5-1. 디렉터리 구조

```
data/
├── sessions/
│   └── jnu_storage_state.json         로그인 세션 쿠키 (민감, 비번 없음)
├── raw/                               ── 원문 보존 ──
│   ├── timetable/    <시각>__timetable_current.html
│   ├── syllabus/     <시각>__<과목코드-분반>_<년도-학기>.pdf
│   ├── notice_aisw/  <시각>__<URL을 파일명으로>.html
│   ├── notice_aicoss/ …
│   ├── notice_nccoss/ …
│   └── notice_sojoong/ …
├── meta/                              ── 원문별 메타데이터 ──
│   ├── timetable/ syllabus/ notice_*/   <항목id>.json
├── index/                            ── 중복·수정 판별 인덱스 ──
│   └── <소스>.jsonl                     (timetable / syllabus / notice_* )
├── runlog/                           ── 실행 이력 ──
│   └── <소스>.jsonl
└── processed/                        ── 구조화 결과(파싱 후) ──
    ├── timetable/timetable.json
    └── notices/
        ├── <site>.json                 목록(메타)
        └── <site>/<id>.json            공지별 본문·첨부
```

### 5-2. 원문 파일명 규칙

`<수집시각 YYYYMMDD-HHMMSS>__<항목id를 안전화>.<확장자>`

- 예 시간표: `20260816-031614__timetable_current.html`
- 예 계획서: `20260816-034926__DSC0010-1_2026-2.pdf`
- 예 공지:   `20260816-145320__https:__aisw.jnu.ac.kr_bbs_aisw_64_1051409_artclView.do.html`
  (URL 의 `/` `?` 를 `_` 로 바꿔 파일명으로 씀, 80자 제한)

### 5-3. 메타 파일 — `data/meta/<소스>/<항목id>.json`

원문 1건마다 1개. 코드: [`storage.py`](../src/collect/storage.py) `save_original()`

```json
{
  "source": "notice_aisw",
  "item_id": "https://aisw.jnu.ac.kr/bbs/aisw/64/1013520/artclView.do",
  "url": "https://aisw.jnu.ac.kr/bbs/aisw/64/1013520/artclView.do",
  "raw_path": "data/raw/notice_aisw/20260816-145326__...artclView.do.html",
  "hash": "d6e93e...",             // 원문 내용의 sha256
  "bytes": 871,
  "tag": "service",                // eval / train / service (§5.3)
  "fetched_at": "2026-08-16T14:53:26+09:00",
  "title": "...", "date": "2026-04-13",
  "category": "일반공지", "board": "인공지능학부(학과)"
}
```

`title`·`date`·`category`·`board` 등 뒤쪽 필드는 소스마다 다릅니다(`extra_meta` 로 넘긴 것).

### 5-4. 인덱스 파일 — `data/index/<소스>.jsonl` (중복·수정 판별, §4.3)

한 줄에 항목 1개. `item_id` 로 "이미 본 것인지", `hash` 로 "내용이 바뀌었는지" 판별합니다.

```json
{"item_id":"...","url":"...","hash":"59a1...","raw_path":"...",
 "first_seen":"2026-08-16T14:53:20+09:00","last_seen":"2026-08-16T14:53:20+09:00"}
```

- 같은 `item_id` + 같은 `hash` → **스킵**(원문 다시 저장 안 함).
- 같은 `item_id` + 다른 `hash` → **수정됨**(새 원문 저장, `last_seen` 갱신).
- 공지 수집은 `item_id` 가 이미 인덱스에 있으면 **상세를 아예 다시 요청하지 않습니다**(예의).

### 5-5. 실행 이력 — `data/runlog/<소스>.jsonl` (§4.4)

수집을 돌릴 때마다 한 줄 추가. "언제부터 수집이 멈췄는지"를 사후에 알 수 있습니다.

```json
{"ts":"2026-08-16T14:53:32+09:00","source":"notice_aisw","status":"ok",
 "detail":"","items_new":5,"items_changed":0,"items_total":31}
```

- `status`: `ok` / `failed` / `skipped` / `login_required`
- 실패 시 `detail` 에 원인이 남습니다(예: `robots.txt 가 수집을 금지함`).

### 5-6. 구조화 결과 — `data/processed/`

파싱(결정적, LLM 미사용)을 거친 최종 형태입니다.

**시간표** `processed/timetable/timetable.json` — 코드: [`parse/timetable.py`](../src/collect/parse/timetable.py)

```json
{
  "courses": [
    {"code":"DSC0010","class_no":"1","subject":"인공지능로봇실습",
     "professor":"방도연","type":"대면수업",
     "meetings":[
       {"day":"월","periods":[1,2],"start":"09:00","end":"11:00","room":"도서관별관316"},
       {"day":"수","periods":[1,2],"start":"09:00","end":"11:00","room":"도서관별관316"}
     ]}
  ],
  "source_file":"data/raw/timetable/...html",
  "parsed_at":"..."
}
```

**공지 목록** `processed/notices/<site>.json`

```json
{"board":"인공지능학부(학과)","list_url":"...","parsed_at":"...",
 "notices":[{"title":"...","url":"...","date":"2026-08-10","category":"일반공지","board":"..."}]}
```

**공지 본문** `processed/notices/<site>/<id>.json` (신규 공지의 상세를 받았을 때)

```json
{"title":"(~8/18) 2026년 상반기 도전장학(미래) 선발 안내",
 "date":"2026-08-10","category":"일반공지","board":"인공지능학부(학과)",
 "url":"https://aisw.jnu.ac.kr/bbs/aisw/64/1051409/artclView.do",
 "body":"2026년 상반기 도전장학(미래) 선발 계획을 안내드립니다. ...(593자)",
 "attachments":[{"name":"(붙임1) ...선발계획.hwp",
                 "url":"https://aisw.jnu.ac.kr/bbs/aisw/64/848885/download.do"}]}
```

### 5-7. 용도 태그 (§5.3)

원문 저장 시 `tag` 로 용도를 구분합니다. 나중에 섞이지 않게 수집 시점에 정합니다.

| 태그 | 의미 |
| --- | --- |
| `eval` | 평가셋. 학습에 절대 쓰지 않음(정확도 측정용) |
| `train` | 학습 데이터 생성용 |
| `service` | 실제 서비스 운영 데이터(기본값) |

`collect <소스> --tag eval` 처럼 지정합니다.

## 6. 개인정보·법적 준수 (§6)

| 항목 | 어떻게 |
| --- | --- |
| robots.txt | 공지 수집 전 확인, 금지 경로는 수집 안 함 |
| 요청 간격 | 항목/페이지 사이 간격(기본 3초), 동시요청 없음 |
| User-Agent | `Univ-Us-Bot/0.1` 로 프로젝트 명시 |
| 개인정보 | 본인 데이터만. LLM·로그·이슈로 **내보낼 때** [`pii.py`](../src/collect/pii.py) 로 이름·학번·전화 마스킹 |
| 비밀번호 | 저장하지 않음(세션 쿠키만) |
| 공개 범위 | `data/` 는 git·이슈·외부서비스로 나가지 않음. 이동은 scp 로 |

> **명부(GetAllUsers) 같은 대량 개인정보 수집은 하지 않습니다.**
> `jnuapi` 의 StdAuth(재학 확인)는 [`stdauth.py`](../src/collect/stdauth.py) 에
> 1인 확인용 최소 구현만 있고, apikey·중간인증서가 있어야 동작하도록 잠가두었습니다.

## 7. 명령어 정리

```bash
# 설치
pip install -r requirements-collect.txt && playwright install chromium
bash scripts/setup-weblogin.sh                 # 서버 로그인 포털용(최초/재시작 후)

python -m src.collect.cli collect-all
python -m src.collect.cli notices all                       # 공개 공지, 전 페이지
python -m src.collect.cli notices aicoss --pages 100 --details 200

# 파싱(구조화)
python -m src.collect.cli parse timetable
```
