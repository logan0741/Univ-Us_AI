# 데이터 라벨링 가이드

> 담당: 정수빈(라벨링·AI 미사용) · 검수: 김건희 · 근거: 수집 계획서 §4.2(테스트셋 50건↑)
> 목표 기능: **"이번주 과제·시험·일정·공지 다 떠"** — 문서에서 날짜 있는 일정을 뽑고, 질문에 맞게 답하기.

---

## 0. 먼저 — 이 데이터가 왜 필요한가 (오해 주의)

"질의–답변 쌍을 모아서 학습시키면, 비슷한 질문에 AI가 알맞게 답한다" — **방향은 맞지만 절반만 맞습니다.**

- 우리 구조는 **기존 LLM + RAG** 입니다. 비슷한 질문에 잘 답하는 능력은 대부분
  **① 기존 LLM의 언어능력 + ② RAG(질문 때 문서를 찾아옴) + ③ 프롬프트·도구 설계** 에서 나옵니다.
- 우리가 만드는 (질의→답변) 데이터의 **1차 용도는 "학습(암기)"이 아니라 "채점과 설계 기준"** 입니다.
  이걸로 파이프라인이 맞는지 **재고**, 틀리면 프롬프트·검색을 **고칩니다**. (파인튜닝을 하게 되면 그때 학습 재료로도 씀 — 선택.)
- 그리고 답은 **고정된 문장이 아니라 "문서 + 오늘 날짜"의 함수**입니다.
  ("이번주 과제"의 답은 이번주가 언제냐에 따라 달라짐.) 그래서 답만이 아니라
  **답의 근거가 되는 사실(문서 속 일정)** 을 함께 라벨링합니다.

**비유**: 우리는 학생(LLM)에게 답을 통째로 외우게 하는 게 아니라, **문제집(정답지)** 을 만드는 겁니다.
학생은 이미 한국어를 압니다. 문제집은 (1) 우리 학교 문제를 잘 푸는지 채점하고,
(2) 틀리면 어디를 고칠지 알려주고, (3) 나중에 과외(파인튜닝)할 때 교재가 됩니다.

## 1. 무엇을 라벨링하나 (우선순위)

| 순위 | 종류 | 입력 → 정답 | 파일 |
| --- | --- | --- | --- |
| **A** | **일정 추출** | 문서 원문 → `events[]` (날짜·종류·제목·근거) | `data/testset/notices.jsonl`, `syllabus.jsonl` |
| B | **질의–정답(QA)** | 질문 → 정답 + 근거문서 + 기대 도구 | `data/testset/qa.jsonl` |
| C | 공지 카테고리(선택) | 공지 → `category` | 위 A 파일의 `category` 칸 |

**A가 핵심.** B는 A가 어느 정도 되면 20~30건. 목표: **A로 50건 이상**(계획서 §4.2).

## 2. 형식 (스키마)

### A. 일정 추출 — 문서 1건 = JSONL 1줄, `events` 와 `category` 만 채운다

```json
{"doc_id":"notice_aicoss_4086","source":"aicoss","doc_type":"공지",
 "title":"...","url":"...","text":"원문(건드리지 말 것)",
 "labels":{"events":[
   {"date":"2026-10-21","type":"시험","title":"중간고사","quote":"중간고사 10/21(화) 3-4교시"}
 ],"category":"학사"},
 "labeler":"정수빈","checked_by":"","tag":"eval"}
```

- **`quote`(근거) 필수**: 그 일정이 나온 **원문 문장을 그대로 복붙**. (검증·RAG에 재사용)
- 일정이 **없으면 `events: []`** 로 둔다(빈 게 정답일 수 있음). 추측으로 만들지 않는다.
- 원문 `text`·`doc_id` 는 **수정 금지**.

### B. 질의–정답(QA) — `expected` 를 채운다

```json
{"qid":"q001","query":"이번주 과제 뭐 있어?","today":"2026-09-14",
 "expected":{"answer":"소프트웨어공학 1차 보고서(9/20)…","evidence":["notice_aicoss_4086"]},
 "expected_tool":{"name":"get_schedule","args":{"range":"this_week"}},"labeler":"정수빈"}
```

- **`today` 기준**으로 답한다("이번주"가 언제인지 고정). `evidence` 에는 근거가 된 `doc_id` 를 적는다.

## 3. 값 목록(enum) — 반드시 이 안에서만

- **`type`**: `과제` · `시험` · `발표` · `수업변경` · `신청마감` · `행사` · `공지` · `기타`
- **`category`**(선택): `장학` · `행사·특강` · `모집·공모` · `학사` · `취업·인턴` · `기타`

## 4. 날짜 정규화 규칙

| 원문 표기 | 라벨 |
| --- | --- |
| `10/21(화) 23:59` | `2026-10-21` (연도는 학기로 채움) |
| `12주차` | 개강일 기준 캘린더로 날짜 환산(모르면 검수자에게) |
| `10/1 ~ 10/10` | 시작·종료 **두 이벤트**로 분리 |
| 상시·미정 | 그 일정은 **제외**(날짜 없으면 안 넣음) |
| 애매함 | 비우고 **아래 '애매사례'에 기록** → 규칙 합의 |

원칙: **원문에 근거해서만 · 추측 금지 · 애매하면 남긴다.**

## 5. 절차

1. **원문 준비**(김건희): `python scripts/make-testset-seed.py` → `data/testset/*.jsonl` 빈칸 생성
   (공지 상세가 적으면 `bash scripts/collect-full.sh notices` 로 먼저 채움)
2. **참고 예시 확인**: `data/testset/_examples.jsonl` — 정답이 어떻게 생겼는지 2건
3. **라벨링**(정수빈): 각 줄의 `text` 를 읽고 `events`·`category`·`labeler` 를 채운다. **AI 사용 안 함**
4. **자가 형식검사**(정수빈): `python scripts/eval-extraction.py --validate` — 오류 0 될 때까지
5. **검수**(김건희): 10~20% 스팟체크, 애매사례를 이 문서 규칙에 반영
6. **완료**: `checked_by` 채우고 저장. 계획서건은 PII 마스킹

## 6. 도구 · 명령

```bash
python scripts/make-testset-seed.py         # 빈칸 원문 생성(라벨 보존 병합)
python scripts/eval-extraction.py --validate # 채운 라벨 형식 검사
python scripts/eval-extraction.py --self-test # 채점기 점검(f1=1.0 이어야 정상)
python scripts/eval-extraction.py --model     # (나중) LLM_MAIN 으로 추출→정답 비교
```

도구는 **JSONL 직접 편집** 또는 구글시트→JSONL 로 충분. 무거운 라벨링 툴 불필요.
