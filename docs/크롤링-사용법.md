# JNU 학사 데이터 수집 — 사용법

> 본인이 로그인한 세션으로 **본인의** 학사 데이터를 가져와 원문으로 저장합니다.
> 수집 파이프라인 계획서 §3(경로 B/D)·§4·§5·§6 을 구현한 것입니다.
> 코드: [`src/collect/`](../src/collect/)

---

## 무엇을 하고, 무엇을 안 하나

| 한다 | 안 한다 |
| --- | --- |
| 내 수강내역·시간표·강의계획서·eClass 과제를 내 세션으로 수집 | ❌ 남의 정보 수집 |
| 원문(HTML/PDF/ICS)을 그대로 보존 | ❌ 명부(이름·전화·학번) 대량 수집 |
| 세션 쿠키만 저장 | ❌ **ID/비밀번호 저장** |
| `data/`(gitignored)에만 저장 | ❌ 원문·세션을 저장소·이슈에 올리기 |

> 이 도구는 `jnuapi` 의 `GetAllUsers`(전 구성원 명부) 같은 대량 개인정보 수집을 하지 않습니다.
> 계획서 §6.1·§8, 기능명세서 1.3(개인정보 최소수집) 원칙입니다.

## 설치

```bash
pip install -r requirements-collect.txt
playwright install chromium          # 브라우저 실물 (~150MB, 필수)
cp .env.example .env                 # 이미 있으면 생략
```

> `requirements-collect.txt` 는 수집 담당만 설치합니다. 브라우저 자동화(Playwright)가 무겁기 때문입니다.

## 로그인 — 비밀번호는 저장하지 않습니다

```bash
python -m src.collect.cli login
```

1. 브라우저 창이 열립니다.
2. **직접 학교 계정으로 로그인**합니다. (프로그램은 비밀번호를 보지도, 저장하지도 않습니다)
3. 로그인을 마치면 터미널에서 **Enter**.
4. 세션 쿠키가 `data/sessions/jnu_storage_state.json` 에 저장됩니다.

> ### ⚠️ 로그인은 화면이 있는 곳에서
> `login` 은 브라우저 창을 띄우므로 **화면(display)이 있는 환경**에서 실행합니다.
> 헤드리스 서버에서 바로 안 되면 아래 [서버에서 실행하기](#서버에서-실행하기)를 보세요.

세션이 살아있는지 확인:

```bash
python -m src.collect.cli status
```

## 수집

```bash
python -m src.collect.cli collect syllabus     # 한 소스
python -m src.collect.cli collect-all          # 전체
python -m src.collect.cli sources              # 소스 목록
```

결과물 (전부 `data/` 아래, gitignored):

```
data/
├── raw/<소스>/<시각>__<id>.html|pdf|ics   원문 (수집 계획서 §5.1)
├── meta/<소스>/<id>.json                  출처·시각·해시·태그
├── index/<소스>.jsonl                     중복·수정 판별 (§4.3)
└── runlog/<소스>.jsonl                    실행 이력 (§4.4)
```

- **같은 내용이면 다시 저장하지 않습니다.** 내용이 바뀌면 새 원문을 저장하고 "수정됨"으로 기록합니다.
- 요청 사이에 간격(기본 3초)을 둡니다. 학교 서버에 부담을 주지 않기 위해서입니다(§6).

### 태그로 용도 구분 (§5.3)

```bash
python -m src.collect.cli collect syllabus --tag eval    # 평가셋 (학습에 안 씀)
python -m src.collect.cli collect syllabus --tag train   # 학습용
```

## eClass 과제·마감은 캘린더(.ics)로

eClass 는 **Moodle** 입니다. 게시판을 긁는 것보다 **캘린더 .ics 내보내기**가 안정적입니다.

1. eClass 로그인 → **캘린더** → **내보내기(Export)**
2. "달력 URL 가져오기(Get calendar URL)"로 나오는 `.../calendar/export_execute.php?...` 주소 복사
3. `.env` 의 `JNU_ECLASS_ICS_URL` 에 붙여넣기
4. `python -m src.collect.cli collect eclass` → `.ics` 원문 저장

URL 을 비워두면 eClass 대시보드 HTML 만 저장합니다(폴백).

## 공개 게시판 공지 수집 (로그인 불필요)

학과·사업단 공지 게시판은 **로그인 없이** 수집합니다 (수집 계획서 경로 C).
세션이 필요 없어 서버/로컬 어디서나 바로 됩니다.

```bash
python -m src.collect.cli notices all       # 4개 게시판 전부
python -m src.collect.cli notices aisw      # 한 곳만
```

| 사이트 | 게시판 |
| --- | --- |
| `aisw` | 인공지능학부(학과) |
| `aicoss` | 인공지능혁신융합사업단 |
| `nccoss` | 차세대통신혁신융합사업단 |
| `sojoong` | 소프트웨어중심사업단 |

- **게시판 전 페이지를 순회**합니다. 새 글이 없는 페이지에서 자동으로 멈춥니다.
  페이지·상세 건수는 옵션으로 조절합니다:
  ```bash
  python -m src.collect.cli notices aicoss --pages 100 --details 200
  ```
- 목록(제목·날짜·URL·구분)은 `data/processed/notices/<사이트>.json` 에,
  신규 공지의 상세 원문은 `data/raw/notice_<사이트>/` 에 저장됩니다.
- **robots.txt 를 확인**하고 허용된 경로만, 요청 간격을 두고 수집합니다 (§6).
- 이미 받은 공지는 다시 받지 않습니다(URL 중복판별).
- **카테고리 분류는 하지 않습니다** — 사이트가 주는 구분값만 담고,
  실제 분류(장학/행사/모집 등)는 나중에 `notice_ai-agent` 가 LLM 으로 합니다.

> 대회 사이트(링커리어·데이콘 등)는 구조·수집 방식이 달라 추후 발전 방향으로 둡니다.

## 서버에서 실행하기

이 서버에서 `*.jnu.ac.kr` 은 **HTTPS 로 접속됩니다**(실측: 응답 ~90ms). 다만 두 가지를 유의하세요.

### 1) 로그인은 화면이 필요합니다

헤드리스 서버에는 브라우저 창을 못 띄웁니다. 두 방법 중 하나:

- **(권장) 로컬에서 로그인 → 세션만 서버로 복사**
  1. 로컬 PC(크롬 있는 곳)에서 `login` 실행 → `data/sessions/jnu_storage_state.json` 생성
  2. 그 파일을 서버의 같은 경로로 복사 (`scp` 또는 VS Code 로 업로드)
  3. 서버에서 `collect` 실행 (헤드리스로 동작)
- **(대안) 서버에서 가상 디스플레이**
  ```bash
  sudo apt-get install -y xvfb        # 재시작 시 사라짐 (docs/서버-작업환경-설정.md)
  xvfb-run python -m src.collect.cli login
  ```

### (권장) 서버에서 웹으로 로그인 — 통합인증·휴대폰 인증 대응

서버(헤드리스)에서 **실제 브라우저를 웹으로 띄워** 직접 로그인하는 방법입니다.
전남대는 통합인증(SAML) + **2차 인증(휴대폰 앱/OTP)** 이라, 이 방식이 그걸 그대로 처리합니다.

```bash
# 서버에서 (최초 1회 · 재시작 후 재실행 — 시스템 패키지라 사라짐)
bash scripts/setup-weblogin.sh

# 로그인 포털 실행
python -m src.collect.cli weblogin
```

그러면 안내가 뜹니다:

```bash
# 1) 로컬 PC 터미널에서 포트 포워딩
ssh -N -L 6080:localhost:6080 <서버 SSH 접속정보>
#    (VS Code Remote-SSH 를 쓰면 포트가 자동 전달되기도 합니다)

# 2) 로컬 브라우저에서
http://localhost:6080/vnc.html
```

3) 열린 화면(= 서버의 실제 브라우저)에 **전남대 통합인증 로그인 페이지**가 나옵니다.
   `아이디` 탭에서 학번/비밀번호 입력 → **휴대폰 앱 인증**까지 직접 완료하세요.
4) 로그인이 끝나 학사행정으로 돌아오면 **자동으로 세션이 저장**되고 포털이 종료됩니다.

> - **비밀번호는 서버에 저장·기록되지 않습니다.** 실제 로그인 페이지에 직접 입력하는 것이고,
>   서버는 그 결과 세션(쿠키)만 `data/sessions/` 에 저장합니다.
> - noVNC 는 `localhost` 전용이라 **SSH 터널로만** 접근됩니다. 외부에 열리지 않습니다.
> - 세션이 만료되면 `collect` 가 `login_required` 로 멈춥니다. 그때 `weblogin` 을 다시 실행하세요.

---

### 세션이 IP 에 묶일 수 있습니다 (로컬 로그인 시)

학교 SSO 가 세션을 로그인한 IP 에 고정하면, **로컬에서 만든 세션이 서버 IP 에서 거부**될 수 있습니다.
이 경우 `collect` 가 `login_required` 로 멈춥니다. 그러면 **로그인한 곳(로컬)에서 수집**하세요.
서버에서 되는지는 한 번 해보면 바로 압니다.

## 주기적으로 돌리기

강의계획서·시간표는 학기 1회면 충분합니다(§4.2). 자주 바뀌는 것만 주기 실행하세요.
`cron` 예시 (세션이 서버에서 유효할 때):

```bash
# 매일 오전 7시 eClass 과제 수집
0 7 * * *  cd ~/Univ-Us_AI && python -m src.collect.cli collect eclass >> ~/collect.log 2>&1
```

세션이 만료되면 조용히 실패하지 않고 `login_required` 로 기록되니, `status` 로 주기적으로 확인하세요.

## 문제 해결

| 증상 | 원인·해결 |
| --- | --- |
| `playwright 가 설치되지 않았습니다` | `pip install -r requirements-collect.txt && playwright install chromium` |
| `세션이 없습니다` | `login` 을 먼저 실행 |
| `login_required` 로 멈춤 | 세션 만료 또는 IP 바인딩 → 다시 `login`, 또는 로그인한 곳에서 수집 |
| `collect sugang_courses` 가 비어 있음 | 수강신청 기간(8/7~8/14) 종료 후 사이트가 닫혔을 수 있음(§1.1) |
| `login` 이 서버에서 창이 안 뜸 | 위 [서버에서 실행하기](#서버에서-실행하기) — 로컬 로그인 + 세션 복사 |

## 데이터 취급 규칙 (수집 계획서 §6)

- **원문·세션은 `data/` 밖으로 내보내지 않습니다.** git·이슈·PR·외부 서비스 금지.
- LLM 프롬프트나 로그·이슈에 쓸 때는 [`pii.mask()`](../src/collect/pii.py) 로 이름·학번·전화를 가립니다(AI 계획서 §8).
- 세션 파일은 **살아있는 인증**입니다. 비밀번호만큼 민감하게 다루고, 만료되면 지워도 됩니다.
- 본인 데이터만, 본인 동의 하에. 외부 공개 금지.

## StdAuth 재학인증 (선택)

`jnuapi` 의 `StdAuth` 는 **가입 시 1인 재학 확인**용입니다(대량 수집 아님). 코드: [`src/collect/stdauth.py`](../src/collect/stdauth.py)

- 학교에서 `apikey` 를 발급받아 `.env` 의 `JNU_STDAUTH_APIKEY` 에 넣습니다.
- `jnuapi` 는 중간 인증서를 안 보내 TLS 체인이 불완전합니다. 학교가 준 중간 인증서를 지정해야 하며,
  **`verify=False` 로 우회하지 마세요**(중간자 공격 위험). 이건 백엔드 가입 기능이라 AI 파트 범위 밖입니다.
